How lcm(5) resolves itself

The function calls itself downward until it hits the base case, then builds the real answer back up — each level walking forward from the level below until it lands on a multiple of its own n.

Call stack: descend, then unwind

Down the left, each call passes a smaller n to the next call. Up the right, each return hands back the value the level above uses as its own smaller.

Inside one frame: the while-loop walk

Zooming into the n = 5 frame: it receives smaller = 12 and steps forward by 12 each time, checking the remainder against 5, until it lands on a multiple of 5.

Why lcm(6) stops at 60, not 6! = 720

At n = 6, smaller = lcm(5) = 60. The loop only ever walks along multiples of 60 — and 60 itself is already divisible by 6, so it stops on the very first check. 720 (which is 6!) is just a much later multiple of 60 that the loop never needs to reach.

The code being traced

def lcm(n)
  return 1 if n == 1

  smaller = lcm(n - 1)
  candidate = smaller
  while candidate % n != 0
    candidate += smaller
  end
  candidate
end
