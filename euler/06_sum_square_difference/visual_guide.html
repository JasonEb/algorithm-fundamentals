Sum vs square, reordered

The whole problem is about what happens when you swap the order of two operations: summing then squaring, versus squaring then summing. Same ten numbers, two different totals.

The two quantities, side by side

For 1 through 10: add them up first and square the result, or square each one first and add those up. The order changes the answer a lot.

V1: two running totals in one pass

Nothing to search or optimize away here structurally — just accumulate both quantities as you go, then compare at the end.

def sum_square_difference(limit)
    sum = 0
    sum_of_squares = 0

    n = 1
    while n <= limit
        sum += n
        sum_of_squares += n * n
        n += 1
    end

    square_of_sum = sum * sum
    square_of_sum - sum_of_squares
end

V2: the loop was never necessary

Both quantities have known closed-form formulas — the sum of 1..n is a triangular number, and the sum of squares has its own classic formula. This is the one case in this batch where the "natural next step" is a formula, not a pattern noticed in the loop.

Sum of 1..n
n(n + 1) / 2
Sum of squares 1..n
n(n + 1)(2n + 1) / 6
def sum_square_difference(limit)
    square_of_sum = (limit * (limit + 1) / 2) ** 2
    sum_of_squares = limit * (limit + 1) * (2 * limit + 1) / 6
    square_of_sum - sum_of_squares
end
