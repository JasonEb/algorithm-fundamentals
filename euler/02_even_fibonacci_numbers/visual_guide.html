Dropping the memo

V2 solves "sum of even Fibonacci terms" with recursion and a memo array. Here's the reasoning that gets from there to a version needing no recursion, no cache, and no more than two variables at a time.

The thought process

  1. Ask what the algorithm actually accesses, and in what order

    V2's outer loop calls fibs(limit), then fibs(limit-1), ... down to fibs(1) — every index, visited exactly once, in a fixed descending order. Nothing is ever requested twice from the outside.

  2. That access pattern is the signal for whether a cache is needed at all

    Memoization earns its keep when a value might get requested again — directly, or through overlapping recursive branches (like naive Fibonacci's call tree). Here, nothing repeats. So the real question becomes: does computing fibs(n) need to look arbitrarily far back, or just a fixed amount?

  3. Look at the recurrence itself

    fibs(n) = fibs(n-1) + fibs(n-2) — producing the next value only ever needs the previous two. Not the whole history. That's what lets an O(n) memo array shrink to two variables.

  4. Reverse the direction on purpose

    V2 computes backward: start at limit, recurse down to the base case, build up via the unwinding stack. Fibonacci is naturally forward — each term comes from the two before it. Walk forward instead of asking "what's term k" repeatedly.

  5. Turn the base case into starting values

    fibs(0) = 1, fibs(1) = 1 becomes the initial state of two rolling variables: a, b = 1, 1.

  6. Turn the recursive relationship into an update rule

    fibs(n) = fibs(n-1) + fibs(n-2) becomes a, b = b, a + b — slide the two-term window forward by one, discarding the term that's now too far back to ever matter again.

  7. Replace "call fibs(k) for k from limit down to 1" with a forward loop

    Run limit times, checking the current term (b) each iteration before advancing — generating terms in order instead of requesting them by index.

  8. The memo array falls out — it isn't removed, it's just never needed

    Once only the last two values are ever held, there's nothing left to cache. It wasn't doing anything conceptually necessary; it existed only because the backward, indexed structure demanded random access that, it turns out, was never actually used.

The sliding window in action

Eight steps of a, b = b, a + b, checking b each time. Only two numbers exist in memory at any point — no array, no history.

Before and after

V2 — top-down + memo
def sum_of_even_fibonacci(limit)
  sum = 0
  memo = []
  while limit > 0
    num = fibs(limit, memo)
    sum += num if num.even?
    limit -= 1
  end
  sum
end

def fibs(n, memo = [])
  return 1 if n <= 1
  return memo[n] unless memo[n].nil?

  memo[n] = fibs(n - 1, memo) +
            fibs(n - 2, memo)
end
Bottom-up — rolling window
def sum_of_even_fibonacci(limit)
  sum = 0
  a, b = 1, 1
  limit.times do
    sum += b if b.even?
    a, b = b, a + b
  end
  sum
end
