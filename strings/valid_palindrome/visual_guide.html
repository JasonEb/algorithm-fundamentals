Valid Palindrome

A genuinely different shape from everything else in this series: instead of two pointers moving the same direction, these start at opposite ends and walk toward each other.

s = "A man, a plan, a canal: Panama"
true
  • Case doesn't matter. Uppercase and lowercase letters are treated as equal.
  • Only letters and digits count. Spaces, punctuation, everything else is ignored entirely.
  • Empty-after-filtering is a palindrome. A string of nothing but punctuation returns true.
  • Up to 2×10⁵ characters. Whatever approach you pick needs to handle real scale.

The trap

Why "clean it, then reverse it" costs more than it looks like

The obvious move: build a cleaned, lowercased copy of the string, reverse it, and compare the two. It's O(n) time — no nested loop this time — but it allocates two entire new strings just to answer a yes/no question.

The optimal version never builds a copy at all. Two pointers read the original string from both ends inward, skipping anything that doesn't count, comparing what's left as they go.

Ruby — the naive version
def valid_palindrome_naive(s)
cleaned = s.downcase.gsub(/[^a-z0-9]/, '')
cleaned == cleaned.reverse
end

Mnemonic: "Clean, flip, compare." Three steps, three passes over the data, two new strings built along the way — correct, but not free.

left and right walk toward each other

Each pointer skips forward past anything that isn't a letter or digit. Once both are sitting on real characters, compare them (case-folded). A mismatch means it's not a palindrome — stop immediately. A match means move both pointers inward by one and keep going. The pointers meeting or crossing without ever mismatching means it's a palindrome.
