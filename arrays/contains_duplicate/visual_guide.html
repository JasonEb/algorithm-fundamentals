Contains Duplicate

The simplest question you can ask a hash set: have I seen this before? No target, no complement, no indices to return — just remember, and check.

  • Return a boolean. Not an index, not a pair — just true or false.
  • "At least twice" is enough. Three or more of the same value still counts.
  • Every element distinct → false. The only way to get false is if nothing repeats at all.
  • Values can be any integer, including negative and very large ones — the array itself can hold up to 10⁵ elements.

The trap

Why checking every pair is O(n²)

Same shape as Two Sum's naive version: for each element, scan the rest of the array looking for a match. It works, but it's a nested loop — O(n²) comparisons.

The optimal version trades that second loop for memory: check a set for the current value, and if it's not there, add it. One pass, one question asked per element.

Ruby — the naive version
def contains_duplicate_naive(nums)
(0...nums.length).each do |i|
(i + 1...nums.length).each do |j|
return true if nums[i] == nums[j]
end
end
false
end

Mnemonic: "Two loops, one skip." Same as Two Sum's naive version, and for the same reason — j starts one past i, so nothing ever gets compared to itself.

A common middle ground: sort nums first, then check every adjacent pair — duplicates end up next to each other. That's O(n log n) time and no extra space, better than the nested loop but still short of the hash set below.
