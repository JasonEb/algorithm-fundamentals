Two Sum

Given an array of integers and a target, find the two numbers that add up to it — and return their indices.

nums (target = 9)
→
Return [0, 1]
  • Exactly one answer. The array is guaranteed to have exactly one valid pair.
  • Can't reuse an element. The two indices you return must be different — even if the values are equal.
  • Return indices, not values. The order of the returned pair doesn't matter.
  • Values can repeat or go negative. [3, 3] and negative numbers are both fair game.

The trap

Why checking every pair is O(n²)

The obvious move is a nested loop: for each element, scan the rest of the array looking for a partner that completes the sum. It works, but for every one of n elements you scan up to n more — O(n²) comparisons.

The optimal version never looks backward with a second loop. It remembers what it's already seen, so by the time the second half of a pair shows up, the first half is already waiting in a map.

One pass, one map

For each value, ask: have I already seen its complement (target − value)? If yes, that's the pair — return both indices immediately. If no, remember this value's index and keep scanning. One pass is enough because by the time a match exists, one half of the pair is already sitting in the map.

Edge cases worth knowing

Duplicates and negatives don't need special-casing

Because the map is only checked before the current value is inserted, an element can never pair with itself — even when two elements share a value. And since the map keys on the actual number, negative values work exactly the same way as positive ones.

Duplicate values: [3, 3], target = 6.

i=0 reads 3. Complement = 6 − 3 = 3. The map is still empty — not found. Remember 3 → 0.

i=1 reads 3. Complement = 3 again. This time the map already has 3 → 0 from the previous element — found! Return [0, 1]. The second 3 never sees itself in the map, only the first one.

Negative numbers: [-3, 4, 3, 90], target = 0.

i=0 reads -3. Complement = 0 − (-3) = 3. Not in the map — remember -3 → 0.

i=1 reads 4. Complement = -4. Not in the map — remember 4 → 1.

i=2 reads 3. Complement = -3. -3 → 0 is already in the map — found! Return [0, 2]: nums[0] + nums[2] = -3 + 3 = 0.
