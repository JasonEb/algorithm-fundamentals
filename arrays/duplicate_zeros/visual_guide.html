Duplicate Zeros

Every zero in a fixed-length array needs to become two zeros, and everything after it shifts right — without a second array, and without touching anything past the original end.

Output
  • Fixed length. The array never grows — it stays exactly as long as it started.
  • Every 0 doubles. Each zero you encounter becomes two zeros, pushing later elements right.
  • Overflow is dropped. Anything that would land past the original length is simply never written.
  • In place. The array is mutated directly — nothing is returned.

The trap

Why "shift on every zero" is O(n²)

The obvious approach works: scan left to right, and the moment you see a zero, insert a second zero right after it and shift everything past that point one step to the right. It's correct — but each shift touches every element after the insertion point. Do that for every zero in an array of all zeros, and you're paying O(n) work, up to n times.

The optimal trick never shifts more than once. It figures out, ahead of time, exactly which elements survive the truncation — then writes the final array from the back, in a single backward pass.

The subtle part

Why walk backward, not forward?

Duplicating a zero always pushes data rightward. If you write forward while reading forward, the write pointer races ahead of the read pointer and starts overwriting cells you haven't read yet. Walking backward guarantees the opposite: the write pointer is always at or ahead of the read pointer, so you finish reading a cell before anything is ever written into it.
