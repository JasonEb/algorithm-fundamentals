Remove Element

Given an array and a target value, wipe out every occurrence of that value in place — the order of what's left doesn't matter, only that the first k slots hold everything else.

The trap

Why deleting-as-you-go is O(n²)

The obvious move is to delete every matching element as you find it — in Ruby, arr.delete_at(i). It works, but every deletion shifts everything after it one step left, which is O(n) per call. An array that's entirely the target value triggers that shift n times.

The optimal version never shifts anything. It just decides, for each element, whether it survives — and if it does, writes it to the next open slot.

One pass, two pointers

A further refinement

Swapping with the end

The version above copies every surviving element forward, even ones that don't need to move. A second optimal approach trades that for fewer writes when val is rare: keep a left pointer scanning forward and a right pointer starting at the end. When left lands on val, swap it with whatever's at right - 1 and shrink the range from the right — instead of shifting the whole remainder, you just move the last element into the gap.

Same array, example 1: [3, 2, 2, 3], val = 3.

left=0 reads 3 (a match) → swap with right-1 (index 3, value 3) → array becomes [3, 2, 2, 3] (no visible change, both were 3) → shrink: right = 3.

left=0 reads 3 again (the swapped-in value) → swap with new right-1 (index 2, value 2) → array becomes [2, 2, 3, 3] → shrink: right = 2.

left=0 reads 2 (not a match) → keep it, left = 1. left=1 reads 2 → keep it, left = 2. Now left == right == 2: done. k = 2, and the first two slots hold [2, 2] — correct, in fewer writes than the copy-forward version needed.
