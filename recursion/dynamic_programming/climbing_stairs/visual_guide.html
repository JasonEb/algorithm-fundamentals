Climbing Stairs

Count the distinct ways to reach the top of n stairs when each move is 1 or 2 steps. It is the usual first dynamic programming problem because the recursion is short and the waste in it is easy to see.

n = 3 has three ways
1-step hop2-step hop
  • Each move is 1 or 2 steps. Nothing else is allowed.
  • Order matters. 1 + 2 and 2 + 1 are two different ways.
  • You must land exactly on step n. Stepping past the top does not count.
  • 1 ≤ n ≤ 45. The largest answer is 1,836,311,903, so plain recursion without a cache will not finish.

The key question

Look at the last move

Every way to reach step n ends with one final move, and there are only two kinds: a 1-step from step n−1, or a 2-step from step n−2. Sort the ways by that last move and the problem splits into two smaller copies of itself.

Last move is a 1-step (from step 3)

3 ways = f(3)

Last move is a 2-step (from step 2)

2 ways = f(2)

n = 4: 3 + 2 = 5 ways
f(n) = f(n−1) + f(n−2)
f(0) = 1  (landed exactly on the top: one way)
f(n < 0) = 0  (overshot: no way)

Common bug: counting moves instead of ways. Passing a running count down and returning it at n == 0 returns how many moves that path took. For n = 2 the path 1 + 1 returns 2 and the path 2 returns 1, so the total is 3, not 2. Return 1 at n == 0: each way that lands exactly on the top counts once, however many moves it used.

Naive recursion

The recurrence, written directly

The formula translates almost word for word into code. It is correct. The trouble is how many calls it makes.

Ruby, the naive version

Mnemonic: "Last move: one step or two." Add the ways from one step below to the ways from two steps below. Stop when you land on the top (1) or overshoot (0).

Naive recursion

O(2ⁿ) time · O(n) space

Every call makes two more calls. Space is only the depth of the call stack.

With a cache

O(n) time · O(n) space

Each value of n is worked out once, then looked up.

Why it matters

The call count doubles as n grows

A call to f(n) makes calls to f(n−1) and f(n−2), so the total grows the way the answer itself does. With a cache, each n from 1 to the target is computed once and every other call is a quick lookup: about 2n + 1 calls in all.

nNaive callsMemoized calls

Where the cache goes. Check it after the two base cases and before the recursive calls. Save the result on the way out, right where the value is computed.

Recap

Complexity

Naive

O(2ⁿ) time · O(n) space

Overlapping subproblems are recomputed on every visit.

Memoized (top-down)

O(n) time · O(n) space

n cached values plus a recursion stack up to n deep.

Next step after memoization: f(n) only reads f(n−1) and f(n−2), so a bottom-up loop can keep just two variables and drop the space to O(1).
